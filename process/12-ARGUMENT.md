# The constructed order (read this before touching the sequence)

## Found vs built

The argument was not found in the text. It was built *from* the text.

What the text gives you (found, by clustering): the themes. What it does
not give you: an order that teaches. Sermon order is the order someone
happened to speak — that is waffle with better organization. The 6-slot
order is an argument someone constructed so a stranger can understand
the thing as fast as possible. Every slot is a load-bearing move. Move
one and the argument falls over. That is the whole difference, and it is
the difference between this project and a playlist.

## The six slots (the template)

Any liberating teaching can be compressed into six moves, in this order,
because the order is the logic of coming to understand anything:

1. CLAIM — what is it? States the thing. Nothing else makes sense
   until this is on the table. (Nibbana: the stilling.)
2. MECHANISM — how does it work? Makes the claim operational instead
   of mystical. (Dependent arising: this happens because that happens.)
3. STICKINESS — why don't you already see it? Names the obstacle inside
   the listener's own experience. This is what turns information into
   diagnosis. (Papancha: the mind keeps making more of everything.)
4. CONSTRUCTION — what does it build in you? Shows the cost: the
   fabrication, the self, the world it sustains. This is what makes
   the teaching urgent instead of interesting.
5. PRACTICE — how do you see through it? Comes FIFTH, never first.
   A method taught before the diagnosis is just technique; taught here,
   it is the only sane response. (In the seeing, only the seen.)
6. REMAINDER — what is left when it stops? Must come last. Put it
   anywhere earlier and it becomes another thing to crave. Put it
   last and it lands as release, not as goal.

The order is constrained, not decorated: 1 anchors everything;
2 makes 1 real; 3 makes it personal; 4 makes it urgent; 5 is only
intelligible after 1–4; 6 must close, never open. Reorder at will —
if the argument still stands, the template was wrong about that text.

## The ritual (bell → question → pause → answer)

Each section opens the same way, every time, no exceptions:

bell → "What is X?" → pause (recollect the answer) → the intro unfolds

The pause is the mechanism: the listener tries to answer before hearing
the answer. That retrieval attempt is what makes the answer stick when
it comes. The bell marks the question as load-bearing. The repetition
is not decoration — the repetition IS the learning, at three timescales:

- seconds: bell → question → pause → answer (within a beat);
- minutes: the motto returns inside every section (refrain, not repeat);
- hours: each zoom layer revisits the whole argument at a new scale
  (Layer 0 seed ≈ 10 min → full series ≈ 20 h).

A "concise" version is not a shorter playlist. It is the same argument
with fewer beats per slot. A "complete" version is not a longer
playlist. It is the same argument with the pauses held longer.

## Portability: what is X?

Replace the central term and the template still holds. A build about
"what is grace" or "what is realisation" asks the same six questions
in the same order, because the order belongs to understanding itself,
not to this text:

1. What is grace? 2. How does it work? 3. Why do we miss it?
4. What does missing it build? 5. How is it seen through?
6. What remains?

What comes FROM the text (found): the themes, the quotes, the similes,
the glosses. What is BUILT onto it (constructed): the slot order, the
questions, the bridges, the bells. Never confuse the two. The
verify.sh gate enforces the boundary: verbatim must be found,
everything else must be built — and labeled as such.
