# The constructed order (read this before touching the sequence)

## Found vs built

The argument was not found in the text. It was built *from* the text.

What the text gives you (found, by clustering): the themes. What it does
not give you: an order that teaches. Sermon order is the order someone
happened to speak — that is waffle with better organization. The 6-slot
order is an argument someone constructed so a stranger can understand
the thing as fast as possible. Every slot is a load-bearing move. Move
one and the argument falls over. That is the whole difference, and it is
the difference between this project and a playlist.

## The six slots (the template)

Any liberating teaching can be compressed into six moves, in this order,
because the order is the logic of coming to understand anything:

1. CLAIM — what is it? States the thing. Nothing else makes sense
   until this is on the table. (Nibbana: the stilling.)
2. MECHANISM — how does it work? Makes the claim operational instead
   of mystical. (Dependent arising: this happens because that happens.)
3. STICKINESS — why don't you already see it? Names the obstacle inside
   the listener's own experience. This is what turns information into
   diagnosis. (Papancha: the mind keeps making more of everything.)
4. CONSTRUCTION — what does it build in you? Shows the cost: the
   fabrication, the self, the world it sustains. This is what makes
   the teaching urgent instead of interesting.
5. PRACTICE — how do you see through it? Comes FIFTH, never first.
   A method taught before the diagnosis is just technique; taught here,
   it is the only sane response. (In the seeing, only the seen.)
6. REMAINDER — what is left when it stops? Must come last. Put it
   anywhere earlier and it becomes another thing to crave. Put it
   last and it lands as release, not as goal.

The order is constrained, not decorated: 1 anchors everything;
2 makes 1 real; 3 makes it personal; 4 makes it urgent; 5 is only
intelligible after 1–4; 6 must close, never open. Reorder at will —
if the argument still stands, the template was wrong about that text.

## The four essays (0, a, b, c) — one question, four depths

Each section's question gets FOUR layers of answer, all present in the
build, all in the fixed presentation order (AXIOM 16):

- **Essay 0 — the compressed answer.** The most concise response that
  still explains the question fully. Tight, exact, no words wasted.
  For §1 it is the motto itself: *"This is peaceful, this is excellent,
  namely the stilling of all preparations..."* — one sentence that IS
  the answer. Essay 0 opens every section: the question is asked, the
  compressed answer goes on screen, the archive voice speaks it (the
  motif). It is the answer first, the expansion later.
- **Essays a/b/c — the expansion.** The graded material already in the
  data (A = gold spine, B = flow, C = depth), heard at expanding
  complexity across the zoom layers: seed → core → gold → pool. Every
  layer is the same argument at greater width; essay 0 never changes,
  it is the seed of all three.

Presentation order inside every layer (bible, do not reorder):
    Nanananda verbatim (text) → plain English (Fish) → Analayo (audio)
The stack on screen mirrors it: his words on top, plain English
underneath, his voice last. The plain English never replaces the
verbatim — it translates it, directly below, in the same moment.

### The formula (how to write a spine question)
A spine question must pass FOUR tests — all human-judged, all fail
fast:

1. **STANDALONE + PRECISE.** Read cold, zero context: the subject
   must be NAMED, and named exactly as that section answers it.
   Naked pronouns fail ("Is any of it real?" - any of what?); so does
   vagueness ("What am I made of?" - body? character? when the
   material dissects the SELF, the question must say "the self"). — the original sin: "Is any of it real?" *is any of WHAT?*
   (M-A10; generalizes M-A9's antecedent rule: no pronoun may need a
   previous answer to resolve).
2. **THE CUT.** The question takes the previous answer and turns it
   into tension for THIS listener, now. Q1 gives you Nibbana — Q2
   doesn't shrug, it pounces: *why don't I see Nibbana right now?*
   A definition answered by a shrug is waste.
3. **CONTENT-FIT.** That section's essay 0 must answer it directly —
   read Q aloud, then A aloud: no leap (the oral test).
4. **PLAIN.** Everyday words, <=9, Fish speaks it flat. Cutting, not
   clever. No doctrine in the question — doctrine lives in the answer.

Method: (a) what did A(n-1) just establish? (b) what is the most
uncomfortable thing to ask ABOUT it right now? (c) does this
section's material answer that? Name the subject from (b) and you have
the question. Change a section's material and you must re-run all four
tests.

### From essay 0 to essay a (how expansion works)
The chain breathes only when micro-sessions are adjacent, so the
LISTEN order is: SEED first (assembly_s0_seed — all six Q->A units
chained, ~4 min; pronouns resolve locally), then ZOOM into each
section, which re-opens with its own question + its essay 0 (the
pair is adjacent again) and grows a -> b -> c from it:

    seed:   [Q1 A1][Q2 A2][Q3 A3][Q4 A4][Q5 A5][Q6 A6]   (the argument)
    zoom:   section n: Qn -> An (anchor) -> essay a -> b -> c (the width)

Never open a section with a question whose referent sits in a
different section's expansion ("part 1 fully expanded, then 'what
keeps IT all going?' = out of context" — the seed carries that edge).
Section openings are self-contained: Qn and An are adjacent, so even
cold listeners re-anchor in one beat. Repetition of Qn at its section
open is deliberate (recognition, not redundancy).

### Build order: ESSAY 0 FIRST (the lesson, learned the hard way)
We built cores first and retrofitted the openers — the seams showed
(Q and A were authored in different sessions and didn't answer each
other: "Why do I suffer?" sitting over a verbatim that never says
suffer). Next time, and as the rule for any rebuild:

1. Write each section's MICRO-SESSION first: the question and its
   compressed answer TOGETHER, as one unit of dialogue.
2. The test is oral: read Q aloud, then A aloud. Any leap = the
   question is wrong (adjust OUR question to the extracted answer —
   never the verbatim; if no extracted answer fits, the section's
   question changes, not the source).
3. Only then build outward: beats, pads, glosses, audio. The essay 0
   is the seed; essays a/b/c grow from it, never the other way.
4. The chain edge-test (above) runs on the micro-sessions, not on
   abstract question labels.

## The ritual (bell → question → pause → plain → answer)

Each section opens the same way, every time, no exceptions:

bell → "What is X?" → pause (recollect the answer) → Fish gives the
plain-English response → essay-0 (verbatim on screen, archive voice) →
the intro unfolds

The pause is the mechanism: the listener tries to answer before hearing
the answer. That retrieval attempt is what makes the answer stick when
it comes. The bell marks the question as load-bearing. The repetition
is not decoration — the repetition IS the learning, at three timescales:

- seconds: bell → question → pause → answer (within a beat);
- minutes: the motto returns inside every section (refrain, not repeat);
- hours: each zoom layer revisits the whole argument at a new scale
  (Layer 0 seed ≈ 10 min → full series ≈ 20 h).

A "concise" version is not a shorter playlist. It is the same argument
with fewer beats per slot. A "complete" version is not a longer
playlist. It is the same argument with the pauses held longer.

## Portability: what is X?

Replace the central term and the template still holds. A build about
"what is grace" or "what is realisation" asks the same six questions
in the same order, because the order belongs to understanding itself,
not to this text:

1. What is grace? 2. How does it work? 3. Why do we miss it?
4. What does missing it build? 5. How is it seen through?
6. What remains?

What comes FROM the text (found): the themes, the quotes, the similes,
the glosses. What is BUILT onto it (constructed): the slot order, the
questions, the bridges, the bells. Never confuse the two. The
verify.sh gate enforces the boundary: verbatim must be found,
everything else must be built — and labeled as such.

### Section titles (CANONICAL, owner 2026-10-25)

The essay's six movements — read back OUT of the build by an outside
read, kept verbatim as the on-screen frames. Two jobs, two homes:
**titles = screen (framing/pointers), questions = Fish (the cut).**

1. What — What is Nibbana?
2. Mechanism — How does experience acquire its apparent structure?
3. Keeps Running — What perpetuates the process?
4. Builds — How is the observer or sense of self constructed?
5. See Through — What changes when that construction is understood?
6. Remains — What, if anything, can be said afterward?

Why canonical: (a) each names its section's MOVE in one line — the
essay's own table of contents; (b) as pointers they deliberately do
NOT cut — a title that interrogates would duplicate Fish's job;
(c) they were derived from the finished structure itself, so they
describe what the build does, not what we intended. The owner's word:
"they are basically pointers." Note Q4 in the chain borrowed the
title's wording because the owner liked it — titles feed questions
when the ear says so.
